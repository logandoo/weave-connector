weave-connector — Backend (API) Design

Transport: MCP over stdio. Config: config.toml (path overridable via WEAVE_CONNECTOR_CONFIG). No HTTP surface. DATABASE_DESIGN: skipped — no data backend (state is in-memory sessions/connections only). PAGE_DESIGN: skipped — backend-only project (no UI).

Daemon · key vault · transcripts

  • Resident daemon owns connections/sessions (unix socket JSON-line RPC, token 0600); the MCP server is a thin client with auto-spawn — sessions survive client restarts. Flat Manager method surface is the single local/remote seam. WEAVE_CONNECTOR_DAEMON=off → in-process.
  • key_ref = "vault:NAME" holds a PEM private key (enroll kind="key", source="file:<path>", confirm-gated).
  • record=true on ssh_shell_open keeps a scrubbed transcript (ssh_shell_transcript).
  • State dir: $WEAVE_CONNECTOR_STATE_DIR or ~/.weave-connector (0700) — audit.jsonl + sessions.json.

Port forwarding · ProxyJump · Named sessions · Enroll

  • ssh_forward_open/list/close — local (-L) forwards over the persistent connection; separate tools for permission gating; local_port=0 picks a free port.
  • Profile jump = "<profile>" — ProxyJump via that profile's connection (credential layer reused; fail-closed on unknown).
  • ssh_shell_open(name=...) — idempotent named sessions; sessions.json holds recovery hints (env KEYS only).
  • ssh_credential_enroll(profile, source) — vault enrollment (local 0600 file) via native hidden dialog or env:WEAVE_ENROLL_*; value never enters tool args/LLM.
  • Tool annotations: read-only tools readOnlyHint, destructive tools destructiveHint.

Credential references (password_ref) — resolve-below-the-model

  • password_ref = "env:VAR" or "keychain:service/account" on a profile; resolved ONLY inside the server process at connect (fail-closed). Plaintext never enters tool arguments or transcripts; it is scrubbed from tool output (best-effort, see above). Plaintext password= in config.toml still works but is discouraged — prefer password_ref.
  • Resolved/used password values (≥4 chars) are scrubbed from returned output — raw, hex, base64, base64url forms, PTY line-wrap tolerant, window-split fragments trimmed (best-effort; transformed values like hashes are out of scope).
  • Append-only audit.jsonl (cwd) logs each resolution: ref, profile, host, ok — never values.
  • Config containing credentials with group/world-readable mode produces a warning in ssh_status.warnings.
  • Boundary: protects model context/logs; does not defend a local same-user process.

Invariants

  • exit_code is produced only by the sentinel marker __WC_EXIT_<n>__; markers are stripped from returned output.
  • cursors are absolute, monotonically increasing per session; buffer cap per max_buffer_bytes.
  • ≤1 pending exec per session; ≤32 sessions total; signals map to control bytes (interrupt=\x03, eof=\x04, suspend=\x1a, quit=\x1c) plus terminate/kill.
  • secrets never leave config.toml: tool outputs carry public profile fields only.

Error model

Tool-level failures return {error: message} payloads (never throw across stdio); unknown session/profile ids list the valid ids; dead connections reconnect on next ssh_connect.
